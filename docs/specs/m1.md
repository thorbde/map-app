# M1 plan: countries and maps

- **Status:** the split is proposed and **not yet approved by Thor**. Both questions below were answered by Thor on 2026-11-16.
- **Written:** 2026-11-16, at the end of the M0 session.
- **Spec:** `docs/specs/mvp.md` §1 and §2. **Decisions:** ADR 0010 (map-first shell), ADR 0012 (facts from Wikidata). **Look:** `DESIGN.md`.

## Goal

The first milestone that produces something you can use: the world map as the base of the app, every country clickable, and a panel with each country's facts. No accounts and no essays yet (those are M2 to M4).

**Done when:**
- every country can be clicked in its continent view;
- the shell keeps the map mounted between pages;
- the size budgets hold: 150 KB of JavaScript per page, about 40 KB of it ours, and under about 50 KB compressed per map file.

## Questions for Thor (both decided 2026-11-16)

### 1. What do the map pages show before accounts exist?

**Decided: A, a temporary preview.** A public atlas (B) stays a possible later decision of its own; nothing in M1 is built for it.

The spec's routes all hang off a username (`/u/:username/:continent`), and accounts arrive in M2.

- **A, a temporary preview:** the continent and country pages live at a placeholder address in M1, and are removed when profiles arrive in M4.
- **B, a public atlas:** the same pages become a real feature anyone can browse: the map, the continents, and each country's fact box, with no essays. It fits "Schoolbook comes alive", but the spec doesn't have it.

**Recommended:** A now, and B later as its own decision.

### 2. Network access for the Wikidata script

**Decided: A, allow the host.** The PR 2 session requests a `map-app` environment with `query.wikidata.org` allowed, and Thor approves the prompt. The Default environment stays as it is.

PR 2's script queries `query.wikidata.org`, which a cloud session can't reach by default.

- **A, allow the host for the session.** The script is developed and tested against real data. The agent requests it and Thor approves a prompt. (A `map-app` environment with that host allowed keeps it off the Default environment, which all projects share.)
- **B, the script only ever runs in GitHub Actions.** It's developed against saved sample responses. This works, but Wikidata's quirks show up later.

**Recommended:** A.

### Decided later, in the PR's own plan

- **How the monthly facts PR gets CI** (PR 2). A PR opened with the default Actions token doesn't trigger other workflows (ADR 0012). Options: a fine-grained token stored as a secret, the Claude GitHub App, or Thor re-running the checks.
- **Hand-written pan and zoom, or `d3-zoom`** (PR 6). Hand-written first; a library only if it turns out fiddly, with an ADR entry (ADR 0010).

## Design-system additions (each needs Thor's approval, in its PR)

- **Panel:** the floating panel with the dark header block.

## Useful to know from M0

- **The reference for the look** is the canvas board "Essay · the approved look, following DESIGN.md" (`docs/design/README.md` has the link). `DESIGN.md` has the rules for labels on the map.
- **The mockups' map was generated** with `world-atlas` (the 110m and 50m files), `topojson-client` and `d3-geo`'s Equal Earth projection, so that approach is known to work. `world-atlas` identifies countries by ISO numeric code, and some features (Kosovo, Northern Cyprus, Somaliland) have no code at all. Those packages aren't in the repo yet: adding them needs an entry in ADR 0013.
- **Colours for the map** are tokens already: `color.map.ocean`, `land`, `border`, `written`, `selected`.

## How to run M1: small sessions

The M0 session grew to about 800,000 tokens of context, and every step re-read all of it. A third of its tokens went on reading routine GitHub notifications. To avoid that:

- **One session per PR,** or per two or three small ones. Everything a session needs is in the repo.
- **Don't watch PRs for routine events.** Subscribe to a PR's activity only when it needs babysitting, and stop once CI is green and the review is handled. Thor says when something is merged or failing.
- **Keep bulky output out of the conversation:** search logs for the error instead of reading them whole, and save long output to a file.
- **Batch steps:** each tool round trip re-reads the whole conversation.

### Kickoff prompt for a new session

> Read `CLAUDE.md`, `ARCHITECTURE.md`, `DESIGN.md` and `docs/specs/m1.md`. We're starting M1. First ask me the open questions in `m1.md` that are still undecided, and record my answers in that file. Then write the short plan for the next PR in the split, and wait for my approval before writing code. Keep the session small, as `m1.md` describes.
